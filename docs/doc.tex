\chapter{Purpose and Architectural Truth}
This document is the engineering reference for UMLCAD.V.7. It is designed so that an engineer or isolated coding agent can work from repository evidence rather than conversation history.

\section{Current implementation versus target architecture}
The current repository contains a mathematical/native authority foundation plus a thin .NET semantic and kernel-integration slice. The repository does not currently contain a complete CATIA-scale application layer.

The longer-term system-CAD direction includes feature history, sketches, assemblies, kinematics, sheet metal, drawing, PMI, CAM, simulation services, knowledge, lifecycle, PLM/PDM, and viewer/presentation. Those are roadmap concerns unless backed by current source and executable evidence.

\section{Authority order}
\begin{enumerate}
\item Exact source and contracts at the commit under review.
\item Executable tests and CI evidence for that exact commit.
\item \texttt{docs/MATH_AUTHORITY_ROADMAP.md} and \texttt{kernel/math/GAP_MATRIX.md}.
\item Current documentation.
\item Historical handoff material.
\end{enumerate}

\section{Non-negotiable rules}
\begin{itemize}
\item CPU \texttt{f64} mathematics is the reference behavior.
\item Metal and CUDA accelerate declared workloads; they never redefine mathematical semantics.
\item \texttt{nalgebra} is an implementation dependency, not the public mathematical contract.
\item Tolerance is explicit input, not hidden global state.
\item Unsupported, ambiguous, singular, degenerate, non-finite, and contradictory cases fail closed.
\item Deterministic identity must not depend on addresses, process-local hashes, execution timestamps, or viewer state.
\item Representation and rendering are derived from authoritative results.
\item Every non-trivial capability follows RED, implementation, GREEN, adversarial validation, integration, and exact evidence.
\end{itemize}

\chapter{Authority and Data Flow}
\section{.NET semantic model}
\texttt{CadApplicationBuilder} owns semantic application construction. It registers parts, assemblies, drawings, configuration, and metadata, then canonicalizes that state and derives a SHA-256 build identity.

The semantic schema is \texttt{uml-cad-semantic/1.2.0}. Build packaging uses \texttt{uml-cad-build-package/1.0.0}.

\section{Kernel client boundary}
\texttt{RustKernelService} is a transport and result-validation adapter. It enforces timeout, response-size, HTTP, JSON, identity, reference, and render-artifact consistency checks.

It must not duplicate geometry mathematics merely to compensate for the native kernel boundary.

\section{Compiled result}
The current compiled package schema is \texttt{uml-cad-compiled-model/1.1.0}. It carries application identity, build identity, root nodes, nodes, relationships, representations, topology bindings, source bindings, diagnostics, and optional render-artifact metadata.

\chapter{Mathematical Authority M0--M16}
\section{Closure}
The mathematical roadmap records M0--M16 as closed for the declared certified domains. That means the roadmap milestones are closed; it does not mean every professional-CAD mathematical family is complete.

\section{Authority principles}
\begin{itemize}
\item CPU mathematics defines reference behavior.
\item GPU implementations conform to explicit backend-neutral contracts.
\item OCCT is an optional backend/oracle and never mathematical authority.
\item Exact and analytic mathematics is preferred over sampled display geometry.
\item Convergence requires explicit verification.
\item Rank, nullity, conditioning, residual, step, and terminal-status evidence are explicit.
\item Rejected solver trials do not contaminate accepted-step convergence history.
\end{itemize}

\section{M14 -- CUDA}
The certified CUDA domain is conservative AABB candidate generation. The repository records the implementation as repository-tested but not NVIDIA-hardware-validated because no NVIDIA runner executed the hardware suite. Driver/runtime absence and invalid inputs fail closed, and accelerator candidate output is reconstructed deterministically.

\section{M15 -- cross-backend conformance}
The common accelerator workload requires every CPU reference overlap to appear in the accelerator candidate set. False positives are allowed as broad-phase conservatism. Repeated execution must be deterministic, and malformed candidate sets are rejected.

\section{M16 -- performance and final red team}
M16 records release-mode CPU/Metal measurements for batches 32, 64, 128, 256, and 512. The benchmark is measurement evidence only and does not redefine correctness. The closure record is tied to commit \texttt{3d494ebbffb6f944e3e574ab04234deeffd9f91a}; CUDA remains explicitly hardware-unverified.

\chapter{Testing and Verification}
\section{Layered testing}
The repository uses focused unit/regression tests, Rust integration tests, .NET client tests, real HTTP black-box tests, Python orchestration, raw protocol red-team probes, demo E2E tests, and exact-head CI evidence.

\section{System gate}
\begin{lstlisting}[style=Code]
python3 tests/e2e/run.py
\end{lstlisting}

For release-mode Rust regression as part of the same gate:
\begin{lstlisting}[style=Code]
python3 tests/e2e/run.py --release
\end{lstlisting}

The harness starts the real \texttt{kernel_host} on \texttt{127.0.0.1:8080}, runs the Rust suites, verifies .NET test discovery, executes the framework and black-box suites, executes the demo path, and performs raw HTTP red-team checks. It rejects unintended ignored Rust tests.

\section{Direct commands}
\begin{lstlisting}[style=Code]

\section{Red-team minimum}
Adversarial coverage must include non-finite input, invalid geometry, stale references, malformed payloads, duplicate identities, rank deficiency, degeneracy, extreme scales, and backend disagreement. Structured failure is required; plausible-but-unverified output is not acceptable.

\section{Exact-head rule}
A milestone is green only when the applicable gates execute and pass on the exact commit being accepted.

\chapter{Coding Standards}
\section{Rust}
\begin{itemize}
\item Public semantics are independent of \texttt{nalgebra} types.
\item Authority boundaries validate finite inputs and explicit tolerances.
\item Typed errors are preferred to sentinel values.
\item No silent fallbacks, hidden tolerances, or semantic defaults.
\item Deterministic ordering is required for returned sets, topology, and diagnostics.
\item GPU code requires an explicit CPU-reference conformance contract.
\end{itemize}

\section{C#}
\begin{itemize}
\item Current projects target \texttt{net10.0}, nullable is enabled, and warnings are errors.
\item Semantic packages and results prefer immutable records.
\item Schema, identity, and reference validation occur at process boundaries.
\item Caller cancellation is preserved.
\item Transport adapters remain thin and do not reproduce mathematical authority.
\item Canonical ordering precedes hashing or serialization.
\end{itemize}

\section{Code quality}
Code should make ownership visible. Methods named Evaluate, Solve, Classify, Validate, or Convert must have explicit failure semantics and evidence expectations. Presentation types must not masquerade as engineering truth.

\section{Current implementation boundary}
The implemented code is substantially smaller than the long-term system-CAD architecture. This is intentional. The foundation should not claim ownership of feature areas that have not yet been implemented and validated.

\chapter{Target System-CAD Architecture}
\section{Semantic separation}
Future system-CAD work should preserve:
\begin{enumerate}
\item Specification: design intent and references.
\item Evaluation: deterministic orchestration through explicit domain services and math contracts.
\item Authoritative Result: verified status, provenance, topology/reference evidence, and measurements.
\item Representation: disposable derived assets such as meshes, drawings, or render artifacts.
\end{enumerate}

\section{Planned domains}
Future layers may add part design, sketch, assembly/BOM, kinematics, sheet metal, drawing/PMI, CAM, phenomena simulation, knowledge/configuration, lifecycle/PLM/PDM, and viewer/presentation.

\section{Simulation boundary}
Phenomena Simulation is a reusable scientific service with multiple implementations. It is not equivalent to a single simulator application. CAM can consume the service while the service remains independent of application-specific semantics.

\section{Manufacturing boundary}
CAM must eventually reach deterministic postprocessed NC/G-code. Machine-controller integrations belong behind explicit adapters and must not become geometry or mathematics authorities.

\section{Drawing boundary}
Drawing consumes CAD authority and explicit measurement results. It does not reconstruct exact geometry from display meshes.

\chapter{Agent and Change Discipline}
\section{Repository as shared memory}
Agents synchronize through contracts, tests, evidence documents, exact commit SHAs, and milestone records. Private chat state is never an architectural dependency.

\section{Change procedure}
\begin{enumerate}
\item Inspect exact head and governing documents.
\item Identify semantic ownership and boundary.
\item Establish or confirm RED coverage.
\item Implement the smallest complete change.
\item Run targeted tests.
\item Add adversarial, metamorphic, property, or differential checks where applicable.
\item Run the system E2E gate.
\item Record exact evidence and remaining blockers.
\end{enumerate}

\section{Scope protection}
Do not solve an application-layer problem by changing the mathematical authority. Do not create a second geometry authority in .NET or rendering. Do not widen a contract solely to make an unrelated test pass.

\chapter{Revision Findings}
This revision removes the unstable two-column layout that caused large unused white regions. The document is deliberately one-column across the full A4 text area. There are no \texttt{\twocolumn} or \texttt{\onecolumn} mode switches.

The previous handbook also documented many nonexistent projects and architecture files. Those references have been removed or reclassified as future architecture so the handbook now follows the actual repository tree.

LaTeX output is treated as generated data and is ignored by Git. A CI job builds this handbook with \texttt{latexmk} so future layout or syntax regressions fail validation.

\chapter{Final Invariants}
\begin{enumerate}
\item CPU \texttt{f64} mathematics is authoritative.
\item GPU implementations are conforming accelerators for declared workloads.
\item Mathematical authority does not depend on rendering, HTTP, or UI.
\item Build identity is deterministic and crosses process boundaries explicitly.
\item References and graph identities are explicit; permanent array position is not semantic identity.
\item Unsupported and contradictory engineering states fail closed.
\item Representation is derived and disposable.
\item CAM, drawing, simulation, and viewer layers consume explicit contracts rather than recreate lower-layer semantics.
\item Milestones are green only on exact-head executable evidence.
\end{enumerate}

\chapter*{Closing note}
UMLCAD.V.7 is currently a mathematical/native authority foundation with a thin semantic application and HTTP integration slice. The architecture is intentionally layered so future system-CAD capabilities can grow without duplicating mathematical authority or allowing transport, presentation, or accelerator implementation to redefine engineering meaning.
